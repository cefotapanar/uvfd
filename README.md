# UVFD — контролер за фреквентен регулатор

Самостојна Windows програма (Python + PySide6 + pyserial) за **Winston WSTG600** и
**SUSWE SU650** преку RS-485 (Modbus RTU). Двата бренда се ист хардвер со исто
упатство (Inovance MD распоред на регистри), па една програма ги вози двата.
**Нема врска со ЕРП-от** — ни за ажурирање: новите верзии доаѓаат од GitHub Releases.

## Што прави

| Дел | Што |
|---|---|
| Главен екран | сè што се чита во живо (U0 група): Hz, струја, напон, DC шина, моќност, момент, температура, DI/DO, AI, бројачи, последни грешки; тренд и снимање во CSV |
| Управување | НАПРЕД / НАЗАД / СТОП / JOG / слободно запирање / ресет, зададена брзина (лизгач, поле, брзи копчиња). **Esc = СТОП**. СТОП е секогаш прв на кабелот — никогаш не чека зад читање |
| PC управување | P0-02 → 2 и P0-03 → 9 (трајно), PD-04 timeout → 2.0 s **само во RAM**. Ако PC замолчи, фреквентниот запира (Err16); по исклучување на струја PD-04 се враќа на своето. При „Прекини“ нуди враќање на претходните P0-02/P0-03 — само ако UVFD го вклучило PC управувањето на тој фреквентен |
| Подесувања | категории лево (P0…PD + „Изменети од фабрички“ + „BIOS разлики“), пребарување по код/име/опис, табела, детали со опсег, опции и опис од упатството, запис со проверка (read-back) |
| Прочитај | ги чита сите параметри и ги зачувува под име (бренд, белешка) |
| Вчитај | зачуван профил → спореди со фреквентниот → штиклирај → запиши само разликите, безбеден редослед (P0-10, граници, P1, остатокот) |
| BIOS | верзијата (P7-11) и моделот (P7-10) се гледаат горе. Нова верзија се памети; „Скенирај“ наоѓа кои регистри ги има; против **основната** верзија се чуваат само разликите (ново / нема / друга фабричка вредност) и се гледаат како посебна колона во Подесувања |

## Поврзување

Стандардно UVFD е на фабричката врска на фреквентните: **9600 · 8N2 · адреса 1**
(PD-00=5, PD-01=0, PD-02=1, PD-05=1; SU650 и PD-08=0). Копчето **„Помош“** до „Поврзи“
ги објаснува ожичувањето, PD параметрите и поставувањето од тастатура. **„Пребарај фреквентен“**
ги пробува сите брзини, формати и адреси 1–10, а ако нема одговор кажува зошто: нема никаков сигнал,
само ехо од адаптерот, или погрешна брзина/формат.

## Кој фреквентен е ова / фабрички ресет

Фреквентниот преку кабелот **не ја кажува** моќноста ни серискиот број (ги нема во ниту едно упатство).
Кажува: број на модел P7-10, BIOS P7-11, тип G/P (P0-00), номинален напон P7-08, температура на IGBT
модулот P7-07, а напонската класа се гледа од DC напонот. Панелот „Фреквентен“ ги прикажува; ознаката
(на пр. G600-4T45G · 45 kW) се поставува еднаш по број на модел од `resources/models.json`
(77 модели, `tools/build_models.py`) и се памети во `datairmware.json`.

„Фабрички“ = PP-01 преку 0x1F01 (SU-650 упатство 6.3): 1 фабрички без моторот, 2 бришење историја на
грешки, 3 фабрички со моторот (SU650). Со лозинка (PP-00) прво 0x1F00. Само при запрен мотор; пред тоа
профил „Пред ресет …“; потоа повторно поврзување на 9600 · 8N2 · #1. `write_reg` не може да стигне до 0x1Fxx.

## Безбедност (што софтверот не дозволува)

- `write_reg` не може да запише во 0x1000/0x2000/0x3000/0x7000/0x8000 — старт/стоп и Hz одат
  само преку `write_control`, само од копчињата.
- Параметри се запишуваат секогаш на EEPROM адреса (0xF0xx) и се читаат назад; RAM (0x00xx) само PD-04 timeout-от.
- PF/PP групата никогаш не се допира (PP-01 = 1 брише сè).
- Параметри „само при стоп“ се одбиваат додека моторот работи; „зависи од моделот“ не се штиклираат сами при Вчитај;
  комуникациските (PD) не се пренесуваат меѓу фреквентни.

## Како е сложена

| Датотека | Што |
|---|---|
| `uvfd/modbus.py` | Modbus RTU (03/06), CRC, толеранција на еден вишок бајт (од VFDTool, проверено на хардвер) |
| `uvfd/bus.py` | единствената нишка што зборува на кабелот: команди → мониторинг → чекор од долга работа |
| `uvfd/drive.py` | регистри, U0 мапа, грешки E-xx, идентитет |
| `uvfd/catalog.py` + `resources/catalog.json` | 376 параметри (WSTG600 проверено + SU650 табела + описи од упатството) |
| `uvfd/store.py` | поставки, профили (`data\snapshots`), BIOS регистар (`data\firmware.json`) |
| `uvfd/sim.py` | симулиран фреквентен на ниво на Modbus рамки (ДЕМО режим и тестовите) |
| `uvfd/updater.py` | GitHub Releases → zip → sha256 → robocopy преку придружна скрипта |
| `uvfd/ui/` | прозорци |
| `tools/build_catalog.py` | гради `catalog.json` од VFDTool базата и PDF-от на упатството |

## Развој

```
pip install PySide6-Essentials pyserial pyinstaller
python main.py                 # нормално
python main.py --demo 502      # симулиран фреквентен (BIOS 21 или 502)
python tests/test_core.py      # self-test, без уред
```

## Нова верзија (ажурирање)

1. крени `VERSION` и напиши `CHANGES` во `uvfd/version.py`;
2. commit;
3. `python build.py --release` — тест, exe, `paket/UVFD.zip` + `uvfd.json`, push и GitHub release `vX.Y.Z`.

Секоја пуштена UVFD при старт (или „Провери за нова верзија“) гледа нова верзија и нуди
„Ажурирај“. Папката `data\` никогаш не се презапишува. Од изворен код програмата само јавува.

## Поставување кај корисник

Отпакувај `UVFD.zip` во `C:\UVFD` (не Program Files — мора да може да се запишува), пушти `UVFD.exe`.
Ожичување: A(D+) → 485+, B(D-) → 485-; ако нема одговор, замени ги A и B.
Фабрички врска 9600 8N2, адреса 1 (PD-00=5, PD-01=0, PD-02=1). „Авто“ ги пробува сите.
